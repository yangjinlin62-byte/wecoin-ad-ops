# 02 每日流程

每天固定 5 步。下面每条都是可直接执行的命令。

## 前置

```bash
cd wecoin-ad-ops
# 确认 Chrome 还开着（两个端口）
```

## ① 复盘（看昨天真实数据）

```bash
node scripts/review.js --days=1
```

输出：每户的消耗、成交单、成交额、ROI，并按目标（8/11/40/42）拆开。

**关键判断**：
- ROI < 0.4 的目标 → 今天砍掉；
- ROI > 0.8 的目标 → 今天加量；
- 某个视频/商品持续 0 单 → 换素材。

## ② 拉新增视频

```bash
node scripts/catalog.js sync --account=account1
node scripts/catalog.js sync --account=account2
```

输出：
- 本次新增的视频（`detectedAt` 是今天）；
- 未测过的有效视频清单（用于补测试）；
- 挂链失效/停投的视频（要排除）。

**只投 `2026-07-01` 之后的视频**（配置项控制）。

## ③ 建单

### 3.1 生成计划

```bash
node scripts/build.js --account=account1 \
  --videos=<视频ID或bundle名> \
  --target=8,11,42,40 \
  --bids=95,0.7,650,0.7 \
  --budget=1000,1000,1300,1000 \
  --count=10,8,6,6
```

参数说明：

| 参数 | 含义 |
|---|---|
| `--videos` | 视频 bundle 名，或直接给 exportId（逗号分隔） |
| `--target` | 四个目标：8 成交数 / 11 成交ROI / 42 净成交 / 40 净ROI |
| `--bids` | 对应目标的出价 |
| `--budget` | 对应目标的预算 |
| `--count` | 每个目标建几条 |

### 3.2 预检（必须通过）

```bash
node scripts/create.js --file=<planFile> --account=account1 --dry-run
```

预检会检查：现金、视频日期、商品、出价、预算、重复指纹。**不通过不要强行建**。

### 3.3 正式建单

```bash
node scripts/create.js --file=<planFile> --account=account1 --confirm=YES
```

输出：`okCount`、`payFile`、`realtimePayFile`。

## ④ 支付

```bash
# 预付费（批量）
node scripts/pay.js --file=<payFile> --account=account1

# 实时（逐条）
node scripts/pay.js --file=<realtimePayFile> --account=account1 --mode=realtime
```

**要点**：
- 批量支付会**轮询等待**，条数越多等得越久（50 条约几分钟）；
- 实时支付遇到「连续 3 条未到账」会停下，通常是免密失效，让用户扫码；
- **不要连续重试**，报 `-9 系统错误` 说明太快，分批（≤5 条/次）并间隔 30 秒。

## ⑤ 复核（2-4 小时后）

```bash
node scripts/review.js --days=1 --by=target
```

看：
- 哪些目标真出单；
- 哪些目标 0 消耗（可能是账户被限）；
- ROI 是否达到预期。

## 每日检查清单

- [ ] 两户现金够不够（`cashFloor` 之上）
- [ ] 有没有待支付堆积（说明免密失效）
- [ ] 计划是否都在加热中（`exportStatus=9`）
- [ ] 有没有 0 消耗 >24h 的计划（列清单给用户，不擅自取消）
- [ ] 复盘数据是否用 indicator（不是 order-list 的 actualCostQuota）
