# 04 排障手册

按现象查处理方式。**遇到问题先停手，不要连续重试。**

## 平台错误码

### 4294954295 / 「系统错误」/ 「操作过于频繁」

**原因**：短时间调用接口太多，被限流。

**处理**：
1. 立刻停止所有脚本；
2. 等 10-15 分钟；
3. 恢复后**低频**操作（每次间隔 ≥1 秒，批量查询而不是逐条）。

### 11770120

**原因**：399 的成交数/净成交数，预算不足出价的 2 倍。

**处理**：预算改成出价 × 2。
- 600 → 1200
- 650 → 1300
- 700 → 1400

### 11770175 / 「当前账户加热订单过多」

**原因**：这个账户当前加热中的订单太多（接近上限）。

**处理**：
- 减少今天的建单量；
- 或等存量订单结束（24h 自然到期）；
- **不要靠反复重试**，会持续报错。

### 11770028 / 「号码包非法或者未完成校验」

**原因**：`excludeUinPackageIds` 里的名单 ID 在这个账户不存在或未校验通过。

**处理**：
- 每个账户的名单 ID **不同**，不能把 A 户的名单 ID 抄给 B 户；
- 需要在该账户后台重新上传名单并等待校验；
- 或者暂时清空 `excludeUinPackageIds` 再建单。

## 支付问题

### 支付返回 `-9 系统错误`

**原因**：批量支付太快，或批量太大。

**处理**：
- 分批（≤5 条/次）；
- 每批间隔 30 秒；
- 遇到 -9 立刻停，等 10 分钟再继续。

### 「连续 3 条实时扣费未到 status=2，疑似免密失效」

**原因**：免密支付过期（24 小时有效）。

**处理**：
- 让用户在平台**扫码重新授权**；
- 扫码后重新支付；
- **不要反复重试**。

### 批量支付显示 0 单完成，但 depositStatus 是 5

**原因**：支付等待时间不够（条数越多转账越慢）。

**处理**：
- 按条数延长等待（50 条约 3-5 分钟）；
- 轮询查询 `getPromotionOrderList` 的 `exportStatus`（2 或 9 = 成功）。

## 页面/CDP 问题

### `fetch failed` / `CDP 连不上`

**原因**：Chrome 没启动，或被杀掉了。

**处理**：重新启动 Chrome（见 `01-快速开始.md`）。

### `headers not captured on 9444`

**原因**：页面没发出接口请求（可能停在登录页或 404）。

**处理**：
1. 检查页面 URL 是否是 `promote/pages/platform/order-list`；
2. 如果是登录页 `login.html`，需要扫码；
3. 如果是 404 路径，导航回正确 URL。

### CDP 页面卡死（`CDP timeout: Runtime.evaluate`）

**处理**：
1. 结束那个 Chrome 的进程树；
2. 用同样的 `--user-data-dir` 重启；
3. 重新导航到订单列表。

## 投放效果问题

### 计划都在加热中，但 0 消耗、0 曝光

**原因**：可能是账户级限制，不是计划问题。

**处理**：
- 检查是不是**连用户手动建的计划也 0 消耗**（如果是，就是账户问题）；
- 检查余额是否充足；
- 如果确认是账户问题，只能找平台客服，代码解决不了。

### 某个目标一直 0 单

**原因**：
- 出价不对（成交数太低或 ROI 太高）；
- 视频素材不行；
- 定向太窄（排除名单太大）。

**处理**：换素材、调出价、检查名单。

## 排查顺序（推荐）

```
1. 接口通不通？（CDP 能连吗、能拉到订单吗）
2. 钱够不够？（现金 / 微信豆）
3. 计划状态正常吗？（status=2、exportStatus=9）
4. 数据口径对吗？（用 indicator，不是 actualCostQuota）
5. 定向/出价/素材对吗？
6. 账户是不是被限？（连手动计划都不动）
```
